Second-Brain Audit & Blindspot Report

Core thesis: the binding constraint is not capture or synthesis — both work. It is trust decay between runs. The system already demonstrated its dominant failure mode: it slept for six weeks (2026-06-09 → 2026-07-21), during which 28 of 41 provenance paths died, both stale-claim review deadlines blew past, and the manifest silently disagreed with the wiki. The wiki is only as trustworthy as its last dream sequence, and nothing triggers the next one.

Sources for this report: a repo-wide complexity audit (ponytail) of all 57 tracked files, plus a blindspot pass grounded in wiki/lint.md, outputs/briefs/2026-07-21-dream-sequence.md, wiki/source_manifest.jsonl, the docs, and the dream-sequence skill. Measured state: 41 manifest records, 14 source pages, 16 concept pages, 7 git commits, last dream run 2026-07-21.

Critical  Trust is actively decaying

1. The loop has no heartbeat

blindspot passtemporal dynamics

Finding — Stale-claim review windows ("re-verify in 7 days / 30 days") are time-based promises, but nothing runs on time: the schedule-dream-sequence skill exists and is not enabled (docs/second-brain-architecture-and-usage.md, "Remaining gaps").

Justification — This is the root cause behind most other findings. Lint duties (stale review, provenance integrity) accrue with wall-clock time, not with new captures — a zero-capture week still creates work. The misconception "I'll run it when I capture something" is exactly how the six-week gap happened. Without a heartbeat, the system degrades into a static wiki with expired warranties.

Fix direction — Enable a weekly scheduled dream sequence with a "no-new-content" fast path that runs only the lint phases, and define what it does when it finds overdue claims it cannot web-verify itself.

2. Provenance rot is structural, not an accident

blindspot passponytail: deletedata lifecycle

Finding — raw/ is a pointer into the living projects tree, not a copy. Any folder later moved or deleted kills provenance for already-processed knowledge. This has already happened to 68% of records: 26 manifest records point at raw/today_06082026/ (deleted) and 2 more at a relocated inbox folder — 28 of 41 dead.

Justification — Provenance (a resolvable path from wiki claim back to raw file) is the one thing this design says it values over disk space. "Register-don't-copy is free" is false: it trades disk for provenance durability. At the churn rate of a working projects tree, every future batch will rot the same way. The decision (annotate as wiki-only vs. restore and re-register) has been pending since the 2026-07-21 dream report.

Fix direction — Make the pending decision, prune or tombstone the 28 dead records. Longer term: content-addressed snapshot at capture time — copy only the registered text files (each <2 MB) into a hash-named KB-local store so provenance survives raw-tree churn.

3. No transactionality between ledgers

blindspot passintegrity

Finding — Each dream run is a hand-executed multi-file transaction performed by an LLM across manifest, processed.md, index, trackers, and pages. Demonstrated failure: the herk batch's wiki pages were created 2026-06-09 while the manifest said unprocessed for six weeks, plus an accidental double registration (runs 063425/064602).

Justification — LLM diligence approximates "usually consistent," not atomic. With no deterministic checker, the next skew will again be found by accident, months later. The ledger layer is the vault's differentiating asset; if it silently drifts, everything downstream inherits the drift.

Fix direction — A scripted, non-LLM invariant checker as phase 0 of every dream run: every processed manifest record has a matching processed.md row and existing pages; every source page has a live manifest record; no duplicate registrations. Fail loudly.

5. raw/ write-protection is a promise, not a mechanism

blindspot passsecurity / enforcement

Finding — docs/selective-capture.md states it plainly: the junction into the projects tree "does not prevent writes at the OS level." Read-only is policy only.

Justification — Every dream run gives an LLM write tools in a repo containing a live pointer into your real projects. One bad tool call can modify or delete actual project files — damage outside the vault, not recoverable from the vault's git. Encoding repairs in July show the agent does rewrite many files per run; the blast radius just hasn't included raw/ yet.

Fix direction — Cheapest OS-level guard: an NTFS deny-write ACL on the junction target for the agent context, or a pre-write hook rejecting any path under raw/. Compare effort and failure modes; pick one.

7. Encoding corruption is a recurring platform hazard

blindspot passintegrity

Finding — PowerShell 5.1 encoding traps already corrupted 9 wiki files (UTF-8 BOMs, mojibake em/en dashes), repaired in the 2026-07-21 run. Every dream run rewrites many files; lint has no encoding check.

Justification — This is a repeatable regression, not a one-off: the same platform trap fires on every Set-Content/Out-File write. The fix is already known in your memory files ([IO.File] with explicit BOM-less UTF-8) but is not encoded where it matters — the lint layer and the dream-sequence skill's safety rules.

8. Compounding on second-order sources with no evidence grading

blindspot passepistemics

Finding — Most of the corpus synthesizes generated summaries of auto-caption transcripts, not primary material — the lint notes say so explicitly. Source pages carry Limitations sections, but concept pages aggregate across sources and do not inherit any quality grade.

Justification — A concept "grounded in 2+ sources" may be grounded in two paraphrases of paraphrases. Confidence silently launders upward as claims move from source pages into concepts. You won't feel this until you act on one of those claims.

Fix direction — Add an evidence-tier field (primary / transcript / generated-summary) to the source template; propagate the weakest tier into each concept page's claims; re-grade the 16 existing concepts.

9. Two brains with overlapping mandates and no boundary

blindspot passecosystem economics

Finding — This wiki and the cerebras brain (632k rows over ~/Downloads/projects — the same tree raw/ points at) both claim recall over your material; a gbrain MCP server with pages/links/jobs also exists. Nothing written decides which is authoritative for what, or where a new source goes.

Justification — "They're complementary" is the misconception: unmanaged overlap means double ingestion cost and contradictory answers with no tiebreaker — you'll trust whichever brain answered last. This should be settled before further investment in either.

Fix direction — One-page boundary policy: wiki = curated synthesized claims with provenance and lint; cerebras brain = bulk recall. Define the routing rule for a new source, and whether dream reports feed the cerebras brain.

10. The skip ledger defines what the brain can never know — nothing audits it

blindspot passcoverage

Finding — Capture's allowlist, 2 MB cap, and binary/PDF skips silently shape the corpus. .vtt transcripts were invisible until noticed and fixed 2026-07-21. wiki/source_scan_skipped.jsonl records every skip, but no phase reads it. Broader: the raw mount lists hundreds of project folders; 41 files are registered — the brain's coverage of your actual work is a rounding error.

Justification — The .vtt bug is one instance of a general pattern: exclusion rules fail silently, and near-zero coverage is fine only if it's a deliberate choice rather than an accident of defaults.

Fix direction — Lint sub-check aggregating the skip ledger by reason and extension, surfacing top unknown_extension patterns. Separately: list the top 10 raw folders by recency and flag which are uncaptured.
