## Summary

Greg Isenberg and Theo Tabah define an AI-native organization as one where people manage agents, agents read from and write back to the company, and the company gets smarter over time through a living context layer. The episode is about operating design, not generic AI enthusiasm: structuring goals, tools, skills, evals, context, prototypes, and feedback loops so AI work compounds instead of staying isolated chat sessions. The durable moat is not "we use AI" — it is the ability to capture context, turn repeated work into skills/skill-chains, run evals, and feed live customer signal back into the system.

## Source-Backed Claims

- "AI native" is an operating model, not a tool stack.
- Three-layer model: people provide strategy/taste/judgment/trust/communication; agents execute tool-using loops; context gives agents institutional memory.
- Humans own the bookends — defining the problem, judging quality, building trust, communicating, making strategic calls.
- Everyone becomes a manager of agents, so prompt skill alone is insufficient; people need delegation, evaluation, and taste.
- Evals define what "good" means; without quality checks, speed creates noise rather than leverage.
- Skills capture repeatable playbooks; skill chains combine playbooks into higher-order workflows.
- The context layer is a loop: capture, curate, store, execute, experience — agents both retrieve from and update shared memory.
- Speed matters because it converts ideas into customer signal quickly (a same-day prototype + usability test beats a static strategy memo).
- Service businesses get more valuable by packaging the people+agents+context system for a niche.
